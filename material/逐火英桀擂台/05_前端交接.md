## 一、项目是什么（30 秒）

- 崩坏3 风格的「电子斗蛐蛐」网页游戏：**13 名逐火英桀**按 91 场赛程自动对战，**玩家只押注，不操作战斗**。
- **赛季 23 天**：D1~D22 每天 4 场（12:00 / 14:00 / 17:00 / 20:00），D23 压轴 3 场（14:00 / 17:00 / 20:00），共 91 场。
- 每天签到得金币 → 押注当日场次 → 开赛自动结算 → 赛季末出双榜。23 天一个轮回。

## 三、战斗规则语义（渲染回放时需要理解的东西）

| 规则 | 内容 |
|---|---|
| 先手 | 速度高者每回合先手；同速按位次（Ⅰ 先于 Ⅱ） |
| 回合 | 每回合双方各行动一次（被眩晕则跳过该回合） |
| 能量 | 普攻命中 **+25**、受击 **+15**；满 **100** 自动释放主动技能并清空（约 3 回合一轮） |
| 普攻伤害 | `max(1, 攻击 − 防御)` × 随机浮动 ±20% |
| **会心** | **全局 32% 概率 ×2.5**（苏另有被动暴击，日志带`〔暴击〕`） |
| 护盾 | 一切伤害先扣护盾（"无视护盾"的真伤除外） |
| 胜负 | 一方 HP 归零即败；**120 回合双方存活 = 平局**（押注退本金） |
| 状态 | 眩晕（跳过一回合）｜减速（速度−4，2 回合）｜封印（被动失效 1 回合）｜星之印记（每层每回合 2.4 点真伤，先扣护盾，每 2 回合衰减 1 层，上限 4 层）｜护盾（上限 35） |

回放事件里能看到的动作名：`普攻` / 各角色主动技能名（如 `黄金之歌`、`妖精水晶箭`、`画笔轻点`、`旭光壁击`、`星辰穿透`）。

## 四、押注与结算（前端必须实现的公式，全部真源在 `economy.json`）

### 4.1 签到（金币产出）

```
每日签到 = 600 + 100 × min(连签天数, 10)     → 满 10 天连签后固定 1600/天
```

### 4.2 下注

| 规则 | 值 |
|---|---|
| 单场单侧下限 | **200**（余额不足 200 不可下） |
| 上限 | **无上限** |
| 窗口 | 当日 00:00 开盘 → **开赛前 5 分钟封盘** → 开赛结算 |
| 平局 | **全额退本金**（不抽水、不赔付） |

### 4.3 赔率三层（**显示与结算是两回事，别混**）

```
① 基础赔率（开盘展示）   rates.json：clamp((1 − 5%) / 市场胜率, 1.05, 19.0)

② 显示赔率（实时刷新，仅展示）
   w = min(1, 当前总池 / 20000)
   池赔率_侧 = 总池 × (1 − 抽水率) / 该侧池
   显示赔率_侧 = clamp( w × 池赔率_侧 + (1 − w) × 基础赔率_侧 , 1.05, 19.0 )

③ 结算赔率（唯一真实赔付，pari-mutuel）
   每 1 金币赔付 = 总池 × (1 − 抽水率) / 胜方池
   → 押胜方 200 金币 = 200 × 该值；押负方全损；平局全额退
```

### 4.4 抽水档位（按单场总池）

| 总池 | 抽水率 |
|---|---|
| < 5,000 | 3% |
| 5,000 ~ 50,000 | 5% |
| ≥ 50,000 | 8% |

### 4.5 结算示例（对照实现用）

- 某场总池 20,000（左侧 12,000 / 右侧 8,000）→ 抽水档 5%。
- **左侧胜**：每 1 金币赔付 = `20000 × 0.95 / 12000 = 1.583`；押左 200 → 得 **316.7**；押右全损。
- **平局**（本赛季第 74 场是平局，开发时可拿它验证）：双侧全额退本金。

### 4.6 鲸鱼提示

某侧投注占比 **> 90%** 且该侧显示赔率 **< 1.05** 时，界面提示"该侧已无获利空间"。（数学：超大额投注会自我稀释赔率，甚至押中也会亏——提示而非禁止。）

## 五、战斗回放（`replays.json` 规格）

### 5.1 结构

```jsonc
{
  "meta": { "seed_base": 20261015, "seed_formula": "match_seed = seed_base * 1000 + match_id", ... },
  "matches": [
    {
      "match_id": 1, "day": 1, "time": "12:00", "tag": "噬界之蛇与猫",
      "left":  { "key": "mobius", "name": "梅比乌斯" },
      "right": { "key": "pardo",   "name": "帕朵菲莉丝" },
      "winner": "帕朵菲莉丝",        // 平局为 null
      "draw": false,               // true = 平局（退本金）
      "turns": 6,
      "p_left": 0.546, "p_right": 0.454,          // 基础胜率
      "left_odds": 1.74, "right_odds": 2.09,     // 基础赔率
      "log":    ["◆ ...释放主动...", "格蕾修(105) 普攻 科斯魔(92) → 7.9", ...],   // 原始行
      "events": [ ... ]                                            // 结构化事件（用这个）
    }
  ]
}
```

### 5.2 事件文法（5 种 type，`events` 数组，按时间序）

| type | 字段 | 说明 |
|---|---|---|
| `cast` | `actor`, `skill` | 释放主动技能（`◆ 名字 释放主动【技能名】`） |
| `hit` | `actor`, `actor_hp`, `action`, `target`, `target_hp`, `damage`, `crit` | **一次攻击**。`actor_hp`/`target_hp` 是行动后的实时血量——**血条渲染直接用它** |
| `crit` | — | 全局会心标记，出现在它修饰的 `hit` **之前**；`hit.crit` 已回填 `true`，**样式以 `hit.crit` 为准**，本事件可做"会心！"闪烁动效 |
| `effect` | `text` | 一切状态/回复/印记/护盾行（`  ↳ ...`） |
| `stun` | `actor` | 该角色本回合被眩晕跳过 |

统计口径：91 场共 1704 事件（hit 978 / crit 318 / effect 226 / cast 179 / stun 3），无未解析行。

### 5.3 渲染建议

- **事件流 feed**：逐条滚动播放，`hit` 更新双侧血条，`crit` 高亮伤害数字，`cast` 插技能演出，`effect` 飘状态字。
- `turns` 给进度感（第 X 回合 / 上限 120）；`draw=true` → 结算页显示"平局·退本金"。
- 播放控制：1x/2x/跳过到结算。

## 六、双榜（前端必须实现的公式）

> 为什么有两张榜：金币榜奖励"攒钱+波动"（爽感），眼力榜奖励"跑赢市场"（眼光）。**不要**只做一张。

### 6.1 金币榜（coin board）

| 项 | 规则 |
|---|---|
| 指标 | 金币持有量（余额） |
| **资格** | 赛季内**参与下注 ≥ 20 场**（参与场次 = 下过注的场次，**含平局场**）——防"只签到不下注"的挂机号霸榜（实测挂机号拿 3.23 万、能排第 51 名，若不设资格线它会进前列） |
| 名额 | 前 100 |
| 并列 | 金币 ↓ → 参与场次 ↓ → 命中率 ↓ → 昵称字典序 |
| 展示 | 名次 / 昵称 / 金币 / 参与场次 / 命中率 / 本赛季净收益（金币 − 签到累计） |

### 6.2 眼力榜（accuracy board）

```
z = (实际命中数 − 期望命中数) / √Σp(1−p)
期望命中数 = Σ(每场所押方向的"市场胜率")     ← p 取 rates.json 的基础胜率
命中率 = 命中场数 / decided；decided = 分出胜负的下注场次（平局不计）
```

| 项 | 规则 |
|---|---|
| **资格** | **decided ≥ 45 场**（半个赛季，保证统计意义） |
| 名额 | 前 100 |
| 并列 | z ↓ → 金币 ↓ → 昵称字典序 |
| 展示 | 名次 / 昵称 / decided / 命中数 / 期望命中数 / 命中率 / 期望命中率 / 超额（pt）/ **z 值** / 金币 |

**⚠️ 实现坑（必读）**：
1. `期望命中数` 的记账时机是**下注时**：用户押下那一刻，按 `rates.json` 的该侧基础胜率把 p 累加进该用户的 `expected`；**不要**在结算时用显示赔率反推。
2. **不要直接排命中率**——设计侧已验证过：命中率榜会与金币榜排出同一批人（对局本就均衡在 40~60%、赔率公平定价，"押得准"几乎全是运气）；且一路押热门的人命中率天然 61%，其实是"跟着市场走"（z 仅 0.76），会被 z 指标正确降权。
3. 平局场次：**不进** `decided`、**不进** `expected`（退本金，什么也不记）。

### 6.3 周期

- **赛季榜**：23 天一结算（与赛程轮回对齐），赛季末定格。
- **日榜**：每日 23:59 快照一次（可先只做赛季榜，日榜是锦上添花）。
- **赛季重置**：每轮回清空重排（金币可保留，榜单资格线按新赛季重新计）。

## 八、坑清单（每条都真踩过或真算过，必读）

1. **CSV 全部 UTF-8 with BOM**：JS 读取后首行表头可能带 `\ufeff`（`match_id` 变成 `\ufeffmatch_id`）。读入后统一 `str.replace(/^\ufeff/, '')` 或对首字段做剥离；`fetch().text()` + 手动 split 时尤其注意。JSON 文件无 BOM，不受影响。
2. **`characters.json` 的 `atk` 是浮点**（如 20.39）——是平衡调参的产物；展示保留 1 位小数，任何计算不要取整。
3. **`rates.json` 的 pair key `"A名|B名"` 顺序不可假设**（遍历序的产物）——`rates["甲|乙"]` 查不到就查 `rates["乙|甲"]`。
4. **结算的胜者必须 = `replays.json` 的 `winner`**（种子约定 `20261015 × 1000 + match_id`）。显示赔率只管展示，**赔付只按池公式**（4.3③）。若你另行演算且种子不同，"回放"和"结算"会对不上——这是致命 bug。
5. **上线防剧透（生产模式必读）**：`replays.json` 是种子固定的预生成数据——**看过这个文件的人等于知道整季胜负**。开发期随便用；**上线时**：胜负改由服务端在开赛时演算（同一引擎 `sim/battle.py`，种子用服务端密钥派生，勿入库勿下发），回放事件**结算后**才下发给前端。
6. **平局**：`winner = null`、`draw = true`（本赛季第 74 场是平局，可用来测退本金路径）。
7. **眼力榜记账时机**见 6.2 ⚠️。
8. **同一天同一角色不会出场两次**（赛程生成时已验证六项约束，前端不用再校验）。
9. **显示赔率每笔下注后要刷新**（池子变了）；两个 side 的显示赔率要一起重算。
10. 榜单的"参与场次"（含平局）与"decided"（不含平局）是**两个口径**，别混用。

## 十、开发期数据与重新生成

```bash
cd material/逐火英桀擂台

# 模拟 200 名玩家跑完整个赛季（产出榜单样例 + 每日经济指标，可填充开发环境）
```

**有任何公式拿不准的，一律以 `data/economy.json`（经济）和 `data/characters.json`（角色）为准，其次回 `03_经济与赔率.md` / `01_角色设计.md` 查证——不要凭感觉实现。**
