# 逐火十三英桀 · 赛博斗蛐蛐

13 名逐火英桀的回合制自动对战 + 押注游戏 —— **设计文档 + 数据 + 可跑模拟器**。

> 玩法定位：沿用崩坏3 官方网页竞猜活动「电子斗蛐蛐」的骨架（回合制自动战斗 + 竞猜券押注），
> 玩家**只参与押注**，不介入战斗过程。

## 快速开始

```bash
cd material/逐火英桀擂台

# 1) 生成赛程（91 场，含六项硬约束自动校验）
python sim/gen_schedule.py

# 2) 跑平衡模拟（2000 局/对 快扫 ≈10s）
python sim/simulate.py --games 2000 --tag quick

# 3) 看对局均衡分布（B 方案验收指标）
python sim/gap_report.py

# 4) 经济与赔率赛季验证（200 玩家 / 23 天 / 91 场，含守恒校验）
python sim/economy.py --players 200

# 5) 正式终验（可选，2 万局/对 ≈2.5 分钟）
python sim/simulate.py --games 20000 --tag final
```

产出：`data/schedule.csv`（赛程）、`data/schedule_odds.csv`（91 场赔率）、`data/win_matrix.csv`（13×13 胜率矩阵）、
`data/economy_sim.csv`（每日经济指标）、`04_平衡报告.md`（每轮记录）

## 核心设计

**战斗骨架**（继承官方活动）：速度定先手｜伤害 = 攻击 − 防御｜生命归零即败｜120 回合双方存活判平局

**增强层**：能量条（普攻+25/受击+15，满 100 放技能）｜连击（多段技能）｜伤害类型（普通/半防穿透/无视防御/无视护盾）｜全局 ±20% 演出浮动

**无元素系统**（主人拍板）：克制关系全部由技能机制实现。

**赛制**：91 场 = 首循环 78 场（每人与其他 12 人各打 1 场）+ 复赛 13 场（每人再加 2 战），每人合计 **14 战**；D1~D22 每天 4 场、D23 压轴 3 场（三条羁绊战）；**同一天内同一角色不得出场两次**。

**经济与赔率**（阶段 6 完成 → [`03_经济与赔率.md`](03_经济与赔率.md)）：每日签到 600 + 连签加成 100×10（上限 1600/天）｜单场最低押注 200、无上限｜抽水 3%/5%/8% 按池规模分档｜**三层赔率**（基础赔率标定 → 池式结算 → 显示锚定平滑）｜平局退本金。
赛季验证（200 玩家）：金币周转 3.0 倍、实际抽水 7.79%、**破产 0 人**、**守恒校验精确为 0**。

**赛季目标：双榜并行**（主人 2026-10-16 决定，取消兑换里程碑）——
**金币榜**（持有量，资格：参与 ≥20 场，防挂机号霸榜）+ **眼力榜**（超额命中显著性 z，资格：分出胜负 ≥45 场）。
模拟结果：挂机号 3.23 万只能排第 51 名，金币榜首 10.5 万（**3.3 倍**）；眼力榜正确降权了"一路押热门"的跟风者（同是 61% 命中率，z 仅 0.76 vs 榜首 2.44）。详见 [`03_经济与赔率.md`](03_经济与赔率.md) 第四节。

## 平衡状态（v6.7 定稿）

**终验：20000 局/对 × 78 对 = 156 万局**

| 指标 | 结果 |
|---|---|
| **无碾压局（<10%）** | **0 组** ✅ |
| **无硬克制（<15%）** | **0 组** ✅ |
| **最差对局下限** | **30.5%**（目标 ≥30%）✅ |
| 30~70% 区间覆盖 | **78 / 78（100%）** ✅ |
| 每场双方 40~60% | 59 / 78（75.6%） |
| 13 人总胜率 | **47.8% ~ 53.7%**（跨度 5.9 点）✅ |
| 平局率 | 1.4%（押注退本金）|

**结论**：每场对局都不会出现"谁上谁赢"的碾压，最坏也是 70/30；赔率分布约 **1.4~2.9**，有热门冷门但无必输局。

### 关键发现：碾压局要靠"加大偶然性"消除，而不是压缩属性差距

四组对照实验证明了这一点（详见 [`01_角色设计.md`](01_角色设计.md) 第五节）：

| 做法 | 碾压局 | 40~60 达标 |
|---|---|---|
| 基线 v3.9 | 8 | 24 |
| 逐组微调 | 17 ❌ | 23 |
| 加"削峰伤害" | 19 ❌ | 26 |
| **全面扁平化**（属性 ±3%、机制减半） | **32** ❌❌ | 6 |
| **加大偶然性（会心 32%×2.5 + 自动让分）** | **0** ✅ | **59** ✅ |

原因：胜负由"击杀回合数之差"决定（普遍 1~3 回合），压缩属性不会缩小这个差，只会让机制差成为主导、结果更两极；能产生六四开的只有**高方差事件**与**角色间强度对齐**（自动让分实测 11 个胜率点/每点攻）。

**13 人总胜率被压到跨度仅 5.9 点（47.8%~53.7%）**——没有绝对强者：总胜率最高的爱莉希雅（53.7%）仍会输给 5 人。

## 三条工程教训（本项目踩出来的真坑）

1. **单一数据源**：平衡参数必须由 `characters.json` 驱动。曾出现"引擎里十几处数值写死、json 调参全不生效"的事故——历轮调参成了幻觉，收敛当然失败。
2. **系统必须有随机源**：8 个纯被动角色无任何随机触发点 → 对局完全确定性 → 胜率矩阵出现大量 0%/100% 退化线（押注玩法直接失效）。引入 ±20% 演出浮动后消失。
3. **整数阈值会造成悬崖**：小数值系统里 ±1 点属性可能价值 30+ 个胜率百分点（实测：凯文 +1 攻 = +31 点；科斯魔盾 28→30 使胜率从 25.9% 跳到 51.8%）。细调请用**浮点参数**，重大改动前先跑单场 verbose 验证机制而非硬调数值。
