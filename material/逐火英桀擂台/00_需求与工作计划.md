## 一、需求确认（我的理解，请核对）

| 项 | 内容 |
|---|---|
| 题材 | 逐火十三英桀（13 人） |
| 战斗形式 | **原版回合制的自动战斗**（沿用官方「电子斗蛐蛐」活动骨架） |
| 玩家角色 | **只参与押注**，不参与战斗操作 |
| 增强机制 | 能量条 / 连击 / 元素克制（已确认，具体规则待设计） |
| 赛程规模 | 91 场，每人 14 战；23 天一个轮回 |
| 每日场次 | 每天 4 场；最后一天 3 场（91 = 22×4 + 3） |
| 排程约束 | **同一天内同一角色不得出现在多场战斗中** |
| 金币来源 | 每日签到 |
| 押注机制 | **动态赔率池**（按实际投注浮动），**带抽水** |
| 交付形态 | 设计文档 + 数据表 + Python 模拟器（可跑 10 万局验证平衡） |

**需要你确认的一处**：你原话是「最后 1 天开 1 场」，但 91 场在每天 4 场的约束下是 **22 天×4 + 第 23 天×3**。若坚持"最后一天只 1 场"，则总场次应为 89（22×4+1），或需要引入淘汰赛制。**此处待你定夺。**

## 三、接下来的工作（阶段分解）

### 阶段 0 · 需求冻结 ← **当前所在**
- 确认本文件
- 拍板待定项（最后一天场次、金币数值、抽水率、落盘位置）

### 阶段 1 · 数据结构设计
- 定义角色 / 赛程 / 赔率 / 经济 四张表的**字段规范**
- **不涉及具体数值**，只定结构

### 阶段 2 · 角色机制设计（13 人）
- 每人：定位 + 4 项基础数值 + 主动技能 + 被动技能
- 设计目标：**机制互不重复**，形成克制网络
- 产出：设计表（先纸面，不进模拟器）

### 阶段 3 · 赛程生成
- 按"每人 14 战 + 每天 4 场 + 同日不重复"的约束排表
- 算法：轮转法（circle method）处理 13 人奇数的轮空
- 产出：91 场赛程表 + 校验（每人场次=14、同日无重复）

### 阶段 4 · 战斗引擎实现
- 回合制骨架 + 能量条 + 连击 + 元素克制
- 要求：**确定性可复现**（随机数种子化）

### 阶段 5 · 平衡迭代
- 跑 10 万局/对，出 13×13 胜率矩阵
- 目标：**每人总胜率 40%~60%**，无无解角色
- 迭代调参直至收敛

### 阶段 6 · 经济与赔率
- 动态池公式 + 抽水
- 用阶段 5 的胜率标定**初始赔率**
- 极端情况保护（冷门爆冷、资金归零）

### 阶段 7 · 交付与落盘
- 全部文档 + 数据 + 源码落盘
- 附可复跑脚本
