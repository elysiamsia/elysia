## 四、工作分解

> 每阶段都必须有**可独立验收**的产出。数值与规则设计在阶段 2 才启动。

### 阶段 0 · 需求冻结 ← **当前**
- **产出**：本文件被主人确认，第六节待定项全部拍板
- **验收**：主人回复确认

### 阶段 1 · 数据结构定义
- **产出**：四张表的字段规范（角色 / 赛程 / 赔率 / 经济）
- **验收**：字段清单经主人过目；**不填任何具体数值**

### 阶段 2 · 角色机制设计（13 人）
- **产出**：`01_角色设计.md` + `data/characters.json`
- 每人含：定位、4 项基础数值、主动技能、被动技能
- 设计目标：机制互不重复，形成克制网络
- **验收**：13 人机制清单无重复；主人确认后进入阶段 3

### 阶段 3 · 赛程生成
- **产出**：`02_赛程表.md` + `data/schedule.csv` + 校验脚本
- **算法**：轮转法（circle method）处理 13 人奇数的轮空问题
- **验收**（三条硬约束，脚本自动校验）：
  1. 总场次 = 91
  2. 每人出战次数 = 14
  3. 任意一天内，同一角色不出现两次

### 阶段 4 · 战斗引擎
- **产出**：`sim/battle.py` + `sim/simulate.py`
- **验收**：同一种子跑两次结果完全一致（可复现）；能输出逐回合战斗日志

### 阶段 5 · 平衡迭代
- **产出**：`04_平衡报告.md` + 胜率矩阵 CSV
- **目标**：每人总胜率落在 40%~60%；无无解角色
- **验收**：10 万局/对的模拟结果满足上述区间

### 阶段 6 · 经济与赔率
- **产出**：`03_经济与赔率.md` + `data/rates.json` + `data/economy.json`
- 用阶段 5 的胜率标定初始赔率；设计动态池与抽水
- **验收**：模拟一轮完整赛程（91 场 + 随机押注），验证金币不恶性通胀/通缩

### 阶段 7 · 交付与落盘
- **产出**：全部文档 + 数据 + 源码 + 可复跑脚本 + README
- **验收**：`README.md` 的完整度表全部打勾
