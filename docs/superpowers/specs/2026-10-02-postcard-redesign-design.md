# 明信片重做：有她 + 能写自己的字 + 二维码

> **本轮的定位**：把首页的「语录明信片」从**只印台词的空背景卡**，改成一张**看得见她的、
> 能写自己的话的、能带出去的**明信片。
>
> 起草日期：**2026-10-02**
> 需求来源：需求方 2026-10-01 定的两条 + 2026-10-02 的三条补充
> 前置：`docs/HANDOVER.md`、现行实现 `assets/postcard.js`（202 行）

---

## 一、为什么

### 1.1 需求方定的六条

| # | 原话（要点） |
|---|---|
| ① | 要**「有她」** —— 现在只会把台词画在空背景上，**没有立绘** |
| ② | 要能**自己写字**再分享 |
| ③ | 写字时**弹出几条「弹幕」式的预设话术**（贴合当前台词），**可选、可改** |
| ④ | 字数**上限 200 字** |
| ⑤ | 卡上要附**本站链接 + 二维码**，二维码**圆角、跟她配色** |
| ⑥ | 立绘**放左侧**；二维码指向 `elysiad.top` |

### 1.2 摸现状时量出来的两个硬约束

**① 那 8 张立绘不都是抠图。** 实测 `images/*.webp`：

| 类型 | 哪几张 |
|---|---|
| 干净抠图（四角全透明） | `armor-pink`（粉色妖精小姐）、`armor-elf`（嗨爱愿妖精）、`skin-1` |
| 有 Alpha 但**四角实心** | `armor-ego`（真我人之律者）、`skin-4` |
| **无 Alpha，矩形图**（自带背景 / CG / 壁纸） | `skin-2`、`skin-3`、`skin-5` |

⇒ 所以版式**不能按「满幅出血」设计** —— 那样 5 张会露出各自的背景。
**立绘必须放进一块「相片框」里**（圆角 + 细边，按比例 contain），这样三种图源都不会崩。

**② 这 8 张本来就在站点上**（`armor-*.webp` + `skin-1..5.webp`，首页已在用）——
所以「八张全可选」**不增加任何新资源** ✓。

## 三、卡面构成

**进画布的 5 样**：① 立绘 ② 她的台词（`QUOTES.daily`）③ 访客写的字 ④ 二维码 ⑤ `elysiad.top`
**只在页面上、不进画布**：⑥ 弹幕条 ⑦ 输入框与三个按钮

```
┌──────────────── 手机 1080×1440 ────────────────┐
│ ╭──────────────╮                              │
│ │              │  「……只要那些名字不被遗忘，     │
│ │   立绘        │    故事就会得到延续。」        │
│ │   （相片框）   │                              │
│ │   左栏 42%    │  ──────────────────           │
│ │   按比例 contain│  ✎ 访客写的那一句 / 那一段    │
│ ╰──────────────╯   （最多 200 字，自动折行）     │
│                                                │
│                                ▓▓  elysiad.top │
└────────────────────────────────────────────────┘

┌──────────────── 电脑 1200×800 ────────────────┐
│ ╭────────╮  「……只要那些名字不被遗忘，         │
│ │ 立绘    │    故事就会得到延续。」            │
│ │ 左栏 36% │  ────────────────────────        │
│ ╰────────╯  ✎ 访客写的那一句 / 那一段         │
│                                                │
│                              ▓▓  elysiad.top  │
└────────────────────────────────────────────────┘
```

- **竖向分栏在两种比例下都成立**（竖版左栏 42%、横版 36%）
- ⚠ 上面两张示意里**省掉了「—— 爱莉希雅」那一行**（标她的台词的落款）—— 实际**保留**，
  排在台词下、`—— 爱莉希雅` 右对齐
- 文字**左对齐**（现在居中）—— 拼在右栏里居中会显得浮
- 「—— 爱莉希雅」那行**保留**（标的是她的话 ✓）
- 访客的字**不写落款**（不是署名，是「写给别人的话」）

## 四、立绘

| 项 | 决定 |
|---|---|
| 来源 | `images/` 里已在站上的 8 张 webp（3 装甲 + 5 皮肤），**不新增资源** |
| 默认 | **随机一张**（每次打开随机；点「换一张立绘」重抽） |
| 可选 | 8 张缩略图一行（手机可横滑），点了就换 |
| 摆放 | 左栏「相片框」内，**按比例 contain**（不裁切） |
| 框 | 圆角 24px + 1px 细边（用她的 `--glass-border` 色）+ 很淡的内阴影 |
| 混合图源 | 抠图那 3 张在框里露出卡底色；带背景那 5 张整幅填进框 —— **两种都不崩** |
| 状态 | 选中态 + `aria-pressed`（与现有按钮同款写法） |

> ⚠ **新增的界面元素一共四样**（本轮全部新增，别的一概不动）：
> ① 立绘缩略图**一行**（8 张 + 一个「随机」圆片）② **弹幕圆片**（3 个）
> ③ **输入框**（含右下角 `n / 200` 字数）④ 二维码（画在卡上，不是界面控件）
> **不新增按钮** —— 弹幕在输入框**获得焦点时**出现。

## 五、弹幕：贴在台词上的预设话术

### 5.1 交互

1. 输入框**获得焦点**时 → 上方出现 **3 个圆片**（不新增按钮）
2. **点一下 → 那句话填进输入框**（不是直接上卡）—— 访客可以接着改
3. 输入框里的内容一变 → **实时重绘**（防抖 120ms）
4. 换台词（「换一句」）→ **弹幕条跟着换**，但**不清空**访客已经写的字

### 5.2 那 30 句（10 条台词 × 3 句）—— **初稿，先过目**

⚠ 这些是**访客的口吻**，不是她的台词，所以不受「台词必须有出处」那条约束；
但每一句都**贴着它上面那条台词**写。

| 台词 | 弹幕话术（三选一） |
|---|---|
| 「嗨，想我了吗？」 | 想了，所以来看看你。 / 一直在呢。 / 今天也来跟你打个招呼。 |
| 「此后，将有群星闪耀，因为我如今来过；此后，将有百花绽放，因为我从未离去。」 | 那我替你把花开遍。 / 你留下的春天，我们接着往下种。 / 群星我记得，花我也会记得。 |
| 「请将我的箭、我的花、与我的爱，织成新生的种子，带向那枯萎的大地。……」 | 种子收到了，我会带它走很远。 / 你的花，会开在别的地方。 / 人性之华——我会替你看它开出来。 |
| 「悲剧并非终结，而是希望的起始。」 | 那我就从这里开始。 / 谢谢你把结尾改成了开头。 / 记住这句话，撑过了不少日子。 |
| 「毕竟——美丽的女孩子，什么都能做到嘛！」 | 这倒是真的。 / 那我也不认输。 / 既然你都这么说了，我就试试看。 |
| 「我是律者，也是人类，但……更是一位如飞花般绚丽的少女呀♪」 | 你就是你，这样就很好。 / 少女你好呀。 / 比起律者，我更喜欢后面那半句。 |
| 「如你所见，与那个凯文齐名的第二领袖，竟是一位如花朵般娇羞的少女——也就是我啦。」 | 第二领袖，久仰。 / 齐名什么的，你比他会说话多了。 / 娇羞的少女，今天也很可爱。 |
| 「而你将走向未来。然后，就去绽放出独属于你的，无瑕而美丽的光辉吧。」 | 我会的，你也是。 / 那束光，我收到了。 / 借你吉言，往前走。 |
| 「愿你前行的道路有群星闪耀，愿你留下的足迹有百花绽放。」 | 也愿你的道路一样。 / 我把这句也送给别人了。 / 星星和花，我都会替你留意。 |
| 「十三个人向命运发起抗争的故事，不应该随着一个时代的逝去一同消亡，它应当被铭记。」 | 所以我把故事讲给别人听了。 / 一个都不会忘。 / 记住你们，是我做的事。 |

**存放**：新建 `data/postcard-prompts.js`，形如

```js
window.POSTCARD_PROMPTS = {
  '「嗨，想我了吗？」': ['想了，所以来看看你。', '一直在呢。', '今天也来跟你打个招呼。'],
  // …10 条，键**与 quotes.js 的 daily 逐字一致**
};
```

⚠ **键必须与台词逐字一致**（含 `「」` 与省略号写法）—— 对不上就静默没有弹幕。
新工具会守着这件事（§十 ②）。

## 六、二维码

| 项 | 决定 |
|---|---|
| 指向 | `https://elysiad.top/`（**注意带结尾斜杠**） |
| 做法 | **预生成一张静态 PNG 进仓库** —— 不引第三方库、不发外部请求、离线可用 |
| 尺寸 | 240×240（画布上按需缩放） |
| 样式 | **圆角**（4 个定位角单独画）+ 模块 `#5a189a`（她的 `--purple-ink`）、底 `#ffc8dd`（她的 `--pink-mist`）—— 深紫压浅粉，扫描对比度足够 |
| 体积 | 目标 ≤ 4 KB（二维码本身就很小） |
| ⚠ 验证 | **生成后用解码器实扫一次**，确认解出来就是那个 URL —— 不是「看着像二维码」 |

> 💡 为什么不引库：这个站的纪律是**轻、且不依赖外网**（QR 库最小的也要 ~10KB，
> 而域名是固定的 —— 预生成一张图就够了）。

## 七、访客写的字

| 项 | 决定 |
|---|---|
| 上限 | **200 字**（`maxlength="200"`，超出打不进去）+ 输入框右下角显示 `n / 200` |
| 折行 | 按右栏宽度自动折行；**中文按字断、西文按词断**（照现有 `wrap()` 的做法） |
| 字号 | 初始与台词同档；**行数超过右栏高度时逐档缩小**（下限约为初值的 70%，不再小） |
| 空 | 不写字也成立 —— 那部分留空，卡照出 |
| 换行 | 访客自己打的换行**保留**（`white-space` 语义照现在） |

## 八、失败与降级

| 情形 | 行为 |
|---|---|
| 立绘加载失败 / 解码失败 | 左栏画成**只有她配色的空相片框**（不出现破图、不报错） |
| 弹幕文件的键对不上台词 | 那一条没有弹幕（**静默跳过**，不影响出图） |
| `data/postcard-prompts.js` 整个加载失败 | 输入框照常可用，只是没有弹幕 |
| 二维码图片缺失 | 卡上只留 `elysiad.top` 文字，**不报错** |
| 老内核（大陆手机） | 只用 ES5 写法（`var` / 不用箭头函数 / 不用模板字符串）+ 不用 `color-mix()` 之类新语法 |

> ⚠ **绝不抛异常**：一次未捕获的异常会让首页剩下的脚本集体停摆，而页面看上去还好 ——
> 这是本站最贵的一类 bug（HANDOVER §九）。

## 九、硬约束

1. **卡上不出现她的新台词** —— 只印 `QUOTES.daily` 里已有的那 10 条（逐字）
2. **弹幕话术是访客的口吻**，且不与她的台词混在一处渲染（视觉上分得开）
3. **不引第三方库、不发外部请求**
4. **不动** `data/quotes.js` / `#daily` 带子 / 现有三个按钮的位置文案
5. **两档尺寸都保留**（竖版/横版都能写 200 字而不溢出）

## 十、验收

**新增 `tools/check_postcard.py`**（走 CDP 真点，因为现有工具都测不到它：
快照采的是**计算样式**（不含文本）、aria / 减动 / 探索系统那三个断言都不看这段数据）：

| # | 判据 |
|---|---|
| ① | 点一下弹幕圆片 → **输入框里出现那句话** |
| ② | `data/postcard-prompts.js` 的**每个键都能在 `quotes.js` 的 daily 里逐字找到**（≥10 条，且每条都有 ≥3 句）—— 对不上就红 |
| ③ | 输入 200 字 → 画布重绘且**无报错**；再把 `maxlength` 顶开（脚本塞 300 字）→ 画布仍然不溢出（截图比对右栏底边） |
| ④ | 点「保存明信片」→ 画布尺寸正确，且**左栏与二维码位置不是空白**（采样该区域像素，须有非底色像素） |
| ⑤ | 「换一句」之后，**输入框里的字还在** |
| ⑥ | 八张立绘逐张切一遍 → 每次都重绘且无报错（含那 5 张带背景的） |

另有常规三条（照旧）：快照差分**只落在 `index.html`**、aria 10/10、减动 7/7。
