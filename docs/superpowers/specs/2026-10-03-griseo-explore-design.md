## 一、她是谁（决定一切设计的三件事）

| | |
|---|---|
| 位次 / 刻印 | **第 Ⅺ 位 ·「繁星」**（别称『画家』） |
| 生日 | **12 月 21 日**（已在 `data/bdays.js` 里登记 `[11, 21]`） |
| CV | 中 紫苏九月 / 日 木野日菜 |
| 武器 / 属性 | 十字架（超限「往世的星空·心之彩」）/ 异能（少年）· 星尘（成长） |
| 出生地 / 身高 | 穆（Mu）/ 145cm（少年）· 166cm（成长） |

**三件必须贯穿全页的事：**

1. **官方能力「色彩浸染」**——她能**沾染周围人的「颜色」并模仿其行为语气**。
   > 官方原文（画家的追忆·其六，帕朵说的）：
   > 「小格蕾修就是这样的。毕竟是小孩子嘛，对什么东西感兴趣或者是心情好的时候，
   > 就会模仿周围人的行为和语气。」「哎呀，就像是一张白纸啦，**很容易染上周围的颜色**。」
   >
   > ⚠ **这是她的专属互动模块的立足点**（见 §3.3），也是这一页「独一份」的地方。

2. **童真**——用画看世界、送朋友东西、童言无忌。她叫梅比乌斯「阿姨」（拒绝改口叫姐姐）、
   叫阿波尼亚「妈妈」、叫帕朵「姐姐」、叫凯文「叔叔」。

3. **刻印「繁星」的官方机制是「染色 / 颜料 / 色相调和」**（材料包 §五 术语表）。
   → 这直接决定了小游戏的母题（见 §五）。

**关系最深的是科斯魔**（第Ⅸ位·旭光）：他像骑士一样守护她，原本**是他**要登上方舟，
而她看出他害怕孤独、**主动替他去了**。⚠ **科斯魔那一页 2026-10-02 刚做完** ——
这是现成的呼应（见 §3.4）。

### 2.2 不做什么

- **不动任何现有页**（10 页）。这一轮的验收安全网就是「其余 10 页零差异」。
- **不引入任何第三方库**（Phaser / PixiJS 等一律不用）——
  全站 4 个游戏都是**原生 canvas 单文件**，整站 gzip 后 ~23KB 是本站对外的核心优势
  （HANDOVER §10.5）。引一个 1MB 的引擎会把它抹掉，且面向大陆手机会多一分打不开的风险。
- **游戏内不放台词**（站点 UI 文案可以）——这是游戏契约的硬规定（spec §4.5）。
- **不编造**：页面上每一句引号内的台词都必须能在档案馆原文里逐字找到。

## 三、页面构成

### 3.1 配色（已定稿）

**方向：C · 未干的画（修正版 · 多色主角）**

底的暖紫黑是需求方选定的「未干的画」氛围；但**主色从单色紫换成多色渐变**——
因为实测发现：`--bg-deep:#0e0a18`（阿波尼亚）与 C 原案的 `#140f1c` 几乎同色，
而阿波尼亚的主色 `--violet:#9d8fd0` 与 C 原案的 `#c9a0ff` 也几乎同色；
维尔薇又已经占了 teal `#4ecdc4`。**紫色系已经挤了三位**。

> 💡 **格蕾修真正的辨识度不是某一色，而是「多色」**——全站只有她是画画的。
> 所以让「彩色」当主角，而不是再跟已有的紫系抢一个色位。

```css
:root{
  --bg-abyss:#100b13;--bg-deep:#150e18;--bg-paper:#241726;--bg-mid:#3a2440;
  /* 多色颜料（她独有的辨识度） */
  --sky:#7dd3fc;      /* 天青 —— 她的头发 / 星空 */
  --violet:#c9a0ff;   /* 紫 —— 她的裙子 */
  --rose:#ff7aa8;     /* 玫红 */
  --lemon:#ffe066;    /* 柠黄 */
  --jade:#5eead4;     /* 青绿 */
  --gold:#ffd97a;     /* 金 —— 发饰与星，统一强调色 */
  --text:#f2e9f8;--text-dim:#b8a8c8;--text-muted:#7d6e8c;
}
```

- **开场标题**走多色渐变（`background-clip:text`）——一眼「彩色」，不像阿波尼亚的单色紫
- **强调元素（按钮 / 链接 / 边）统一用金 `#ffd97a`**，克制，避免整页花掉
- ⚠ 实际落地后要**和 aponia / villv 两页并排截图核对**（HANDOVER §6.4：颜色类改动用像素差分）

### 3.2 专属特效：`#paintCanvas` —— 「颜料晕开成星」

现有 9 种粒子**全是「点/片往下落」**（花瓣 / 命运丝 / 音符 / 余烬 / 冰霜 / 菩提叶 /
彩纸 / 落樱+刀光），只有 kosma 的 `dawnCanvas` 是往上飘的。

她的母题是「颜色」，所以做**全站唯一会「留下痕迹、并且变色」的粒子**：

- 一颗颜料滴从上方飘落 → 落到画布高度的某处**晕开**一圈（半径渐大、透明度渐低）
- 晕开的颜色从五色里随机取
- 偶发：几颗晕开的光点**凝成一颗四角星**，再淡去（呼应刻印「繁星」）

> ⚠ 与樱花 / 冰尘的区别要一眼看得出：**它们是「点」，这个是「面」**（晕圈）。

### 3.3 专属互动模块：**「她的调色盘 · 色彩浸染」**

**这是这一页最像她的一块，也是全站没有过的机制。**

页面上一个调色盘，盘上是**她的朋友们留下的颜色**（每色对应一位，颜色取自那位朋友的页面主色）：

| 色 | 对应 | 点下去她说（**台词全部有出处**） |
|---|---|---|
| 暖橙 | 帕朵菲莉丝 | 「一起去『搞票大的』……！」（画家的追忆·其六） |
| 墨绿 | 科斯魔 | 「唔……因为科斯魔说，更喜欢这样……」（画家的追忆·其二） |
| 紫罗兰 | 阿波尼亚 | 「嗯，阿波尼亚对我很好，就像妈妈一样。」（画家的追忆·其一） |
| 青 | 梅比乌斯 | 「是梅比乌斯阿姨。」（画家的追忆·其五） |
| 天青 | **她自己** | 「那之后，我就一直在画画。因为阿波尼亚妈妈说这样能帮到大家，画里也有很多朋友。」（画家的追忆·其一） |

**交互**：点一抹色 → 那抹色在调色盘上**晕开** → 页面里「她说话的那一块」**染上那个颜色**
（文字色 / 光晕 / 边框一起变）→ 她说出对应那句话。

> 💡 **为什么是它**：这**不是**「再加一个可点击的东西」——它把她的**官方能力**
> （色彩浸染：沾染别人的颜色并模仿其语气）**变成了看得见的东西**，
> 而且每一句台词都是**她真的在那个人的「颜色」下说出来的**。
> HANDOVER §4.1 第 4 条说「彩蛋该承担这位的性格」——同一个道理。

⚠ **落点**：放进 `#palette` 一节（替代 su 的 `#merit` 功德箱）。
⚠ **点击涟漪排除名单**要包含 `#paletteStage`（照 su 排除 `#muyuStage` 的先例）。
⚠ 每句台词的 `src` 必须**逐字核准**（进核准表）。

### 3.4 三个彩蛋（机制避开既有 15 种）

现有机制清单见 HANDOVER §4.2。已有的：点名字 / 长按名字 / 点专属元素 / 抽卡 /
键盘序列 / 结尾点语录循环 / 连点 6 次 / 双击 / 闲置 25 秒 / 需够 5 次 / 跨彩蛋解锁 /
两次点击间隔 / 顺序点击 / 累计陪伴时长 / 滚动到结尾。

| # | 彩蛋 | 机制 | 为什么是她 |
|---|---|---|---|
| 1 | **《星空下的少年》** | **点那一幅画**（递进：点 → 空白画框 → 再点 → 画面浮出） | 她给**科斯魔**画的画。⚠ **科斯魔那页刚做完**——在这里遇上他，是最自然的呼应。她说的是「我已经画好很多朋友了」那一类**送画**的话 |
| 2 | **那幅空白的画** | **点另一幅画 → 反复点**（第 1 次沉默，第 2 次才说） | 「我为她画出的景象，**只有一片空白**。」——她画不了**爱莉希雅**。全站情感最重的一处呼应（首页就是爱莉希雅） |
| 3 | **你踩到画布了** | **在页面任意处点 → 留下颜料脚印**（累积到第 N 个触发） | 「不能在床单上画画……不能在墙上画画……还不能……」——她记科斯魔定的规矩。**留下痕迹**这个机制全站没有 |

> ⚠ **彩蛋 1 / 2 都是「点画」**（机制同类）——**需求方 2026-10-03 定：保留，不改机制。**
> 理由：这两幅画是她角色弧光里最重的两个锚点，「点画」这个动作本身就是在模拟她
> 「作画 / 观画」的行为；换成「点月亮打招呼」这类新机制，情感重量与角色契合度会断崖式下跌。
> 「雷同才改」的判据在这里不适用——**内容完全不同，且是她最重要的两幅画**。
>
> ⚠ **但两幅画必须有足够的视觉区分度**，免得玩家以为第二个坏了：
> · **科斯魔那幅（彩蛋 1）**：点 → 画面**暖色渐显**（墨绿 + 旭光橙，呼应他那页的配色），
>   **一次比一次多画出来一点**（递进的「显形」）
> · **爱莉希雅那幅（彩蛋 2）**：点 → **始终是空白的画布**，只留一层**极淡的微光**；
>   第二句之后**仍然是空白**——那份「空白」本身就是内容
>
> ⚠ **两幅画在页面上的位置、点击热区互不干扰**，且**都不压住可发现物**
> （HANDOVER §6.4：探索系统那批元素不在快照 SELECTORS 里，压住了看不出来）。
>
> ⚠ 彩蛋 3 的「留下痕迹」与页面已有的**点击涟漪**要**互斥**（涟漪是全局的，彩蛋脚印只在
> 触发的那几次出现）——照 sakura 排除 `#sakuraGameOverlay` 的先例，把新模块的容器
> 加进涟漪排除名单。

### 3.5 成长形态：「大格蕾修」（一节，不做第二页）

**需求方 2026-10-03 定：少年为主 + 成长作一节。**

- **位置**：时间轴里，**「方舟 / 星尘装甲解锁」那个节点之后**，作为一段
  **独立的叙事过渡**（不是又一张档案卡）。
- **构成**：一句 **`给予刻印` 的独白**（有出处）+ **立绘切换**（少年 → 成长）。
  > 首选独白：「星星们住的地方······一定很美吧？你也想和我一起住到那里去吗？」
  > （给予刻印·其十三）——既是「繁星」，又是从少年望向成长的一句。

> ⚠ **具体哪 12 条在本 spec 里不拍板**——写实施计划时**逐条去档案馆核**（台词与 `src` 一起抄准）。
> ⚠ 取材已**实测打通**：档案馆 `content/1676/detail`，**10 个折叠段落全部展开后**

> ⚠ **`给予刻印` 那 17 条是本页的独白池**——sakura 那轮**不用**它（语境不同），
> **kosma 那轮用了**（他的口琴 = 给予刻印·其十四~十九）。格蕾修**可以**用在专属模块或 whisper，
> 但**不混进 finds**（finds 是「事件对话」，混独白会断章）。

### 4.3 取材方法与两条纪律

照 HANDOVER §10.10 一：**渲染 SPA → 点开所有 `[展开]`（判据「剩余 = 0」）→ 按小标题切段 → 收台词**。

- ⚠ **原文照录，一个字不改**（档案馆用 `······` 六个中点，不许「规范化」）
- ⚠ **`src` 形如**：`官方档案馆 · 事件-格蕾修 · 画家的追忆·其一`
- ⚠ **已知源站错字**：「关于绘画·其一」里写的是「**爰**莉希雅」（爰 U+7230 ≠ 爱 U+7231）。
  **这一条建议避开不用**——角色名写错很扎眼。若要用，须先与需求方确认怎么处理。

### 4.4 挑台词的原则

照 mobius `lab-04` 与 sakura 的先例：**哪句台词，放在哪个地方才最成立**。
她的「画」与「颜色」是最好用的母题——比如
「颜料，找不到了……」（给予刻印·其一）放在**调色盘**旁边、
「我喜欢小船，也喜欢月亮先生」（画家的追忆·九）放在**时间轴的方舟那一节**。

## 五、小游戏：「上色」

> **需求方 2026-10-03 定稿**。灵感来自需求方提出的 IO 圈地玩法（《围城大作战》一类），
> 由本站**用原生 canvas 单文件重写**——**不引入 Phaser / PixiJS**（见 §2.2）。

### 5.1 玩法（完整版）

**一句话**：在画布上圈地、上色，把**造物**的领地整个吃掉；你越强，场上越凶。

| 要素 | 设计 |
|---|---|
| **画布** | 一格一格的网格（初始约 **48×32**），空白处是**纸白**（未上色的画布） |
| **玩家** | 起始拥有画布中央一小块颜色（「画布原点」）。**按住并拖动** → 笔尖移动、身后拖出**笔触**（水彩拖尾） |
| **上色** | 松手时，若**笔尖回到自己的颜色上** → 这一笔围出的区域被**填色**（晕染动画）；**没回到 → 笔触淡去**（白画） |
| **造物（AI）** | 场上若干「**褪色造物**」（灰白线稿风）。**它们也有自己的领地、也会自己圈地扩张** |
| **被撞** | 造物碰到**玩家的笔触** → 玩家的笔触**全断**，笔尖**从自己的颜色重新出发**（不是死亡，是「灵感中断」） |
| **反制** | 玩家碰到**造物的笔触** → 造物的那一笔断（对称） |
| **杀死造物** | **把它全部领地染成你的颜色** → 造物消失 |
| **击杀反馈** | 造物消失的瞬间**闪过它自己的颜色**（每个造物登场时**带一种「朋友色」**：墨绿 / 暖橙 / 紫罗兰…）—— 与 §3.3 的调色盘形成**隐性呼应**（需求方 2026-10-03 补） |
| **难度自己喂** | 玩家的地越大 → 造物**数量 +1 / 速度升一档** |
| **阶段** | 累计**杀掉 2~3 个造物** → **画布解锁更大区域**（网格扩张）+ **更多造物**上场 |
| **限时** | **3 分钟**（可随时「收笔」退出） |
| **结算** | 完成度（你的上色格 / 总格）+ 击杀数 + 最高纪录（存 `localStorage`） |

### 5.2 操作（手机优先）

- **手机**：按住拖动。⚠ 手指会挡视线 → 笔尖**跟随手指**，但整体**向上偏移约 44px**
  （手指落点 = 笔尖下方），并 `touch-action:none` + `preventDefault` 防页面跟着滚
- **电脑**：鼠标按住拖动；另给键盘方向键作为备选
- ⚠ **拖动与页面滚动冲突**是这一页最容易踩的坑（探索系统的 `slide` 动词踩过同类），
  **断言要覆盖「拖动时页面没有滚动」**

### 5.3 契约与硬约束（照 spec §4.5 + HANDOVER §10.10 六）

```js
window.ElysiaGames = window.ElysiaGames || {};
window.ElysiaGames.griseo = { title:'上色', hint:'把这张画，涂成你的颜色。', mount: mount };
```

- 单文件 IIFE、`mount(host)` 内 `try/catch`（**绝不抛**）、可重复调用
- 自建遮罩 `#griseoGameOverlay`（`aria-hidden` 同步）、关闭键挂**屏幕角落**
  （离操作区 ≥ **100px** —— sakura 实测 55px 会误触，见 HANDOVER §10.10 五）
- **400ms 保护期**（挡双击 / 浏览器补发的延迟 click）
- **不放台词**：面板文字是站点 UI 文案
- 动画走 canvas（`prefers-reduced-motion` 不关它——它由「开始」显式触发）
- 登记进 `check_explore.py` 的 `GAMES`

### 5.4 ⚠ 技术风险（必须先验，别写到一半才发现）

| 风险 | 说明 | 怎么降 |
|---|---|---|
| **围地填充算法** | 全游戏最容易错的地方。用**洪水填充**（从画布外边界灌，灌不到的空白就是被围住的）比扫描线配对**更好保证正确**。⚠ **边界 case 是坑中之坑**：笔触**紧贴画布边缘**、或**未闭合却贴边**——最容易出「没围住却被填色 / 围住了却没填」（需求方 2026-10-03 点名） | 先写**独立小原型**，把**贴边 / 贴角 / 单格宽通道 / 已有领地贴边**各写一条断言，**验过再进游戏** |
| **AI 不卡死 / 不乱冲** | 造物要自己圈地，行为要看起来「有意图」 | 简单策略：沿向走 N 格 → 绕回领地；卡住就换向 |
| **手机性能** | 网格 + 多造物 + 每帧重绘 | 网格用**离屏 canvas 缓存**，只在格子变更时增量重绘 |
| **难度曲线** | 「地越大造物越快」可能瞬间失控 | 分档（不是线性），且**封顶** |
| **3 分钟偏长** | 现有游戏都是 30 秒量级 | 可随时退出 + 60/90 秒各有阶段性成果（杀第一个造物） |

> ⚠ **这一块的量明显大于 sakura「一瞬」与 kosma「守灯」** —— 计划里要拆成
> 「**算法原型 → 玩家可动 → 造物与碰撞 → 难度与阶段 → 结算**」多步，
> **每一步真跑过再往下**（HANDOVER §九）。

### 5.5 断言（要专门写）

- **通用四条**（`check_explore.py` 的 `GAMES` 已泛化）：开局在动 / 手机上放得下+摸得到 /
  退出键离操作区够远 / 减动下仍在动
- **专属**（照 `check_sakura_judgment` / `check_kosma_judgment` 的模式）：
  ① 拖动能真的上色（上色格数**变多**，不是「画了个圈」）
  ② 被造物撞到 → 笔触断（可证伪：造物笔触与玩家笔触相交的那一帧）
  ③ 玩家领地变大 → 造物数量/速度档**真的变了**
  ④ 杀掉 N 个 → 画布**真的扩张**了
- **每条都要配变异**（把实现故意改错 → 必须报红；⚠ 红的时候**也要看失败原因**，
  别把工具崩溃当成断言抓住了）
