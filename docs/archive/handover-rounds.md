### 三、⚠ 三个踩过的坑（都记在这儿）

1. **`/var/www` 属 root**：往它下面建临时目录必然 Permission denied ⇒ 临时目录全部放站点目录内部；
2. **`git clone` 传大文件被掐**：`curl -I github.com` 1.66 秒 ✅、`ls-remote` 成功 ✅，但完整 clone 报
   `fatal: GnuTLS recv error (-110): The TLS connection was non-properly terminated` ⇒ 大陆机房连 GitHub 的老问题。
   绕法：本机 `deploy.sh`（已可用）／`codeload` tar 包（服务器实测 HEAD 200 / 0.71s）／**Gitee 镜像**（0.22s）；
3. **`--depth=1` 不指定分支**会把仓库留成断头状态（`your current branch appears to be broken`）⇒ 必须 `--branch main`。

### 四、⭐ 后端上线的那个 bug（值得单记）

**现象**：需求方说「献花没显示 44 朵，反而**每次刷新页面增加一朵**」。

**根因**：前端契约（`assets/flowers.js` 顶部注释）写的是 `GET /count → {count}`、`POST /flower → {count}`，
**字段名是 `count`**；我实现成了 `{total}` ⇒ 前端读到 `undefined` ⇒ 判成失败 ⇒ **静默降级成本地计数**
（这正是那份代码里写明的设计：任何情况下都不给访客看错误提示）⇒ 于是每次点击只涨本地那份。

**修法**：后端改成同时返回 `count` 与 `total`（`count` 才是被读的那个）。
**验证**：浏览器实测首页献花区显示 **「这里已收到 44 朵花」** ✅

> 📌 教训：**契约写在代码注释里，就得先去读它** —— 我自己写的后端、字段名却拍脑袋定的。

### 最近一轮（2026-10-15 · 深夜六）：并发卡死的诊断 + Service Worker

**需求方现象**：「网络信号挺好，界面就是加载不出来」；而且「**我和朋友不能同时开网站**，不然特别卡」。

### 一、诊断（都是可复跑的实测，不是猜）

| 压测（本机、连线上、8 倍 CPU 降频 + 模拟 4G） | 结果 |
|---|---|
| 顺序请求首页 × 20 | **20/20 成功**，中位 **282ms**，最慢 760ms |
| **6 个并发请求首页** | 5 个 ~1.0s 成功，**1 个挂死 >15 秒** ❌ |
| 6 个并发请求 `/count`（worker） | 全部 0.7~1.8s 正常 ✅ |
| 6 个并发请求静态 CSS | 全部 ~1.1s 正常 ✅ |
| 首屏传输量 | 首页 **108KB**、凯文页 **49KB** —— **不是体积问题** |

**结论**：**worker 后端没问题、静态资源没问题、我们的 JS/CSS 也不重**；卡的只有「**首页 HTML 这一条路**」。
看 `cf-cache-status` 就明白了：顺序访问 19 次 `HIT` 快（280ms）；并发里挂死的那个是 **`MISS`**。
⇒ **边缘缓存未命中/回源校验时，Cloudflare 把并发请求合并成一个回源，那一步卡住，等它的人一起卡**。
两个人的浏览器几乎同时打开 ⇒ 同时撞上待校验的对象 ⇒ 双双等在那儿。
（客观背景：大陆访问 Cloudflare 免费版常被调度到很远的 PoP，回源那一步本来就慢且不稳。）
